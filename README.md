## Phase 2: 素材・デザイン制作 ✅ 3Dモデルは完了

- 3Dモデル（Tripoで制作）: 子ども恐竜・歴史恐竜・プテラ恐竜・団子恐竜・チケット配り恐竜・父恐竜の
  6体が揃いました。各スポットのストーリーに合わせて割り当て済みです（下記「キャラクター配置」参照）。
- **軽量化処理を実施**: Tripoからの書き出し直後は1体あたり11〜17MBありましたが、`gltf-transform`
  （メッシュ簡略化 + テクスチャ1536px縮小 + JPEG圧縮 + 不要データ削除）で1体あたり1.1〜1.35MBまで
  圧縮しました（約90%削減）。見た目の劣化はほぼありません。最適化済みファイルは
  `assets/models/*.glb` に格納しています。
- 紙マップ（印刷物）のデザイン: 印刷用デザインファイル（AI/PSD等）の制作はこの環境の対象外です。
  必要であれば、レイアウト構成案（掲載要素・QRコード位置・足跡導線の配置案）はテキストでご提案できます。

## Phase 3: Webアプリ開発 ✅ 実働コード＋本番AR実装まで完了

`index.html` / `manifest.json` / `sw.js` / `vendor/three/*` / `assets/models/*.glb` として、以下を実装しました。

- スタート画面（プロローグ、位置情報ONで開始。QR読込の操作はアプリ内には無し＝紙のQRからブラウザ起動で完結する前提）
- マップ画面（6スポット＋ゴールカードのリスト、現在地からの距離表示、足あとトレイルの進捗表示）
- GPS判定ロジック（`navigator.geolocation.watchPosition` + Haversine公式による距離計算、
  各スポットごとの判定半径に基づく自動到着判定）
- ストーリーモーダル（到着時のテキスト演出とヒント表示）
- **本番AR実装**: three.js（`vendor/three/`にローカル同梱、外部CDN不要）でカメラ映像の上に
  スポットごとの.glbモデルをリアルタイム合成表示。指でドラッグして回転操作も可能。
  シャッターボタンでカメラ映像+3Dモデルを合成したPNGを撮影。
- **ゴール（親子再会）演出**: 全6スポット踏破後、恐竜広場（スポット①と同座標）に戻ると
  ゴールカードが解放され、父恐竜と子ども恐竜が並んで表示される専用AR演出が見られる。
- ビジュアルダイアリー（撮影したフォトを`localStorage`に保存し一覧表示）
- 現地テスト用デバッグパネル（緯度経度を手入力してGPS判定をシミュレーション可能）
- 簡易PWA対応（`manifest.json` + `sw.js`によるオフラインキャッシュ）

### 動作確認済み（ヘッドレスブラウザでのテスト）

- スタート→GPS取得→スポット①自動到着→ストーリー→AR（3Dモデル表示・ドラッグ回転・撮影）→ダイアリー保存

### このチャット上でのプレビューについて

このHTMLファイルはこの会話上でも開けますが、**Geolocation APIとカメラアクセスは
サンドボックス環境の権限上動作しません**。実際の位置判定・AR撮影の動作確認は、
Phase 4でデプロイした後にスマートフォン実機で行ってください。デバッグパネルを使えば、
座標を手入力して判定ロジックだけは今すぐ確認できます。

### ファイルサイズについて

3Dモデル6体で合計約7.6MB（1体あたり1.1〜1.35MB）。初回アクセス時にまとめて読み込むと
モバイル回線ではやや時間がかかるため、余力があれば「訪問したスポットのモデルだけ読み込む」
（現状も実装上はそうなっている＝スポットごとに個別ロード）、または`sw.js`のキャッシュ対象に
`assets/models/`を追加してオフラインでも再訪問時は高速化する、といった改善余地があります。

## Phase 4: サーバー準備＆配置 📋 手順のみ（実際のデプロイは要手動）

このAI環境からは外部ホスティングサービスへの直接デプロイができないため、以下の手順で
ご自身の環境から公開してください。

**Vercelの場合:**
1. `dino-app`フォルダ一式（`vendor/`と`assets/`を含む）をGitHubリポジトリにpush
2. https://vercel.com でそのリポジトリをImport（Framework Presetは「Other」でOK）
3. Deployをクリック → 自動的にHTTPSのURLが発行される

**GitHub Pagesの場合:**
1. リポジトリの Settings → Pages → Source を「main」ブランチ / ルートに設定
2. 数分後に `https://(ユーザー名).github.io/(リポジトリ名)/` で公開される

いずれもHTTPS必須（Geolocation APIとカメラAPIはHTTPS環境でのみ動作します）。
`vendor/`と`assets/models/`のフォルダ構造を保ったままアップロードしてください（相対パス参照のため）。

## Phase 5: 現地テスト（実地試走） ⏳ 現地での実施が必要

デプロイ後、実際に①→⑥を歩いて以下を確認してください。

- 各スポットでの実際のGPS誤差と、判定半径（現状25〜50m）の妥当性
- 特に⑤新栄商店街・ガレリア元町、⑥ハピリンは屋根・屋内のため、GPSのみでの自動判定が
  機能しない可能性があります。その場合は「近づいたら手動チェックインボタンを表示する」
  フォールバックの追加を検討してください。
- 実機でのAR表示の見え方（3Dモデルのサイズ感・回転操作の使い勝手・カメラとの合成品質）
- モバイル回線での3Dモデル読み込み速度（特に⑤⑥のような屋根・屋内スポット）
